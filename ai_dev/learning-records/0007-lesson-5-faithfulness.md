# Lesson 5 delivered: faithfulness — the second measurement, the one retrieval can't see

The retrieval spine (lessons 1–4) only answered "did the right chunk come back?" Lesson 5 adds the measurement that scores the answer itself: faithfulness, reference-free, in three steps (decompose → NLI entailment check → supported/total), named by FActScore (arXiv:2305.14251) and RAGAS (arXiv:2309.15217).

**Evidence**: `exercises/lesson0005/faithfulness.py` runs four hand-written (question, gold context, generated answer) cases through a local NLI cross-encoder (`cross-encoder/nli-MiniLM2-L6-H768`, 82M params). Real run output: faithful 1/1 = 1.00; hallucination-sneaks-in 1/2 = 0.50 (second claim "emails the support team" = neutral/not-in-context); right-chunk-wrong-claim 0/1 = 0.00 (neutral); compliance-polarity-flip 0/1 = 0.00 (contradiction — the chunk says "stores no recordings", the answer says "stores recordings"). Overall 2/5 = 0.40. Crucially, in all four cases the context shown is the gold chunk — recall@k is 1.0 by construction, and faithfulness still separates the four. The lesson's punchline: perfect recall and zero faithfulness coexist.

**Implications**: (1) The two-metric model is now fixed: recall@k scores retrieval, faithfulness scores generation — never conflate them. (2) NLI's three labels carry a teaching payload: neutral = invented detail, contradiction = reversed fact (the career-ending one); both score 0, only entailment counts. (3) NLI is a cheap deterministic proxy, not a human auditor — frame faithfulness as a regression number to run every build, escalating to a human on drop. (4) Decomposition is itself a fallible step (`--live` demos LLM decomposition) — the third place errors hide. Next: the capstone — an end-to-end system with citations, running both metrics on every answer.
