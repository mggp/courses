RAG from the ground up

You know what RAG is. By the end of this lesson you will have built one — a script that answers questions from your own documents, no framework hiding the mechanics.

~30 minutes  ·  Python  ·  glossary  ·  quiz component

Why this lesson

A language-learning app needs a tutor that answers from its own course material — vocabulary lists, grammar rules, the learner's mistakes — and never makes things up. A fintech needs answers that can be traced to a source document, because "the model said so" is not a compliance answer. Both are the same problem: retrieval-augmented generation. Your mentor asked if you knew it; this lesson makes you able to say what you'd build.

The whole loop, in one breath

RAG bolts a document store onto a language model. When a question arrives, you search the store for the most relevant excerpts, then hand those excerpts to the model alongside the question. The model's job is to answer from the excerpts, not from its own memory. That is the entire idea — it is credited to Lewis et al., who defined RAG as combining a parametric memory (the model) with a non-parametric memory (a retrievable index of documents):

We explore a general-purpose fine-tuning recipe for retrieval-augmented generation (RAG) — models which combine pre-trained parametric and non-parametric memory for language generation. Lewis et al., NeurIPS 2020

Two phases run at very different frequencies:

Indexonce per document set → Retrieveonce per question → Generateonce per question

Only the knowledge you need

Embeddings: the retrieval key

An embedding is an array of numbers an embedding model produces for a piece of text. Same length every time, no matter the text's length; for the model in this lesson, 384 numbers. Think of it as a coordinate in a strange high-dimensional space where similar meaning sits near similar meaning. Simon Willison calls the resulting search "vibes-based search" — and it is the key trick in all of RAG.

The two spaces don't match up. A question ("what is shot-scraper?") and a statement ("shot-scraper wraps Playwright") use different grammar. Some embedding models handle queries and passages separately for this reason; all-MiniLM-L6-v2 does not, which is fine for a first pipeline.

Chunking: size matters

You don't embed a whole book — a question matches a few sentences, and the model's context window is finite. You split documents into chunks, embed each chunk, and retrieve whole chunks. Chunk size is the first quality knob you'll tune; here we use whole short paragraphs.

Cosine similarity: "how close"

To rank chunks against a question, normalize all vectors to unit length, then take the dot product — this is the cosine similarity: 1 for the same direction, 0 for orthogonal. Willison's implementation is just that:

def cosine_similarity(a, b):
    dot_product = sum(x * y for x, y in zip(a, b))
    magnitude_a = sum(x * x for x in a) ** 0.5
    magnitude_b = sum(x * x for x in b) ** 0.5
    return dot_product / (magnitude_a * magnitude_b)

Source: simonw/llm, and discussed in the embeddings essay.

Generation: grounded, not remembered

The last step is a prompt: retrieved chunks as context, then the question, with an instruction to answer only from the context. The model is still doing the writing — but it is writing from your documents, which is what grounds the answer. This is why RAG cuts hallucination: the model no longer has to invent the facts, only the wording.

Build it

Everything above is ~30 lines. Create a venv and install:

# in a fresh directory
python3 -m venv .venv
source .venv/bin/activate
pip install numpy sentence-transformers openai
Heads-up: sentence-transformers pulls in PyTorch — the install is a few hundred MB, and the first run downloads the all-MiniLM-L6-v2 model (~90 MB) from Hugging Face. One-time cost; everything after is offline.

Save this as rag.py:

"""rag.py — a minimal Retrieval-Augmented Generation pipeline."""
import numpy as np
from sentence_transformers import SentenceTransformer

# ---- your corpus: five one-line "documents" ----
docs = [
    "RAG stands for Retrieval-Augmented Generation.",
    "An embedding maps text into a vector space where similar meaning sits nearby.",
    "Cosine similarity measures how close two normalized vectors are.",
    "Chunking splits a document into pieces small enough to retrieve precisely.",
    "Generation feeds retrieved chunks to an LLM along with the question.",
]

model = SentenceTransformer("all-MiniLM-L6-v2")

def embed(texts):
    vecs = model.encode(texts)
    return vecs / np.linalg.norm(vecs, axis=1, keepdims=True)

doc_vecs = embed(docs)

def retrieve(query, k=2):
    q = embed([query])[0]
    scores = doc_vecs @ q
    order = np.argsort(scores)[::-1][:k]
    return [(docs[i], float(scores[i])) for i in order]

def generate(question, context):
    prompt = (
        "Answer the question using only the context below.\n\n"
        f"Context:\n{context}\n\nQuestion: {question}\n"
    )
    # Swap in any provider you have access to: OpenAI, Anthropic, a local model…
    import openai
    reply = openai.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
    )
    return reply.choices[0].message.content

if __name__ == "__main__":
    question = "How do you measure how close two meanings are?"
    hits = retrieve(question)
    for doc, score in hits:
        print(f"{score:.3f}  {doc}")
    context = "\n\n".join(doc for doc, _ in hits)
    print("\n--- generation (optional) ---")
    # print(generate(question, context))
  1. Run python rag.py. You should see two lines — the chunk about cosine similarity ranked first, the chunk about embeddings second, with scores between 0 and 1.
  2. Ask a different question that doesn't mention the answer's words, e.g. "How does RAG stop the model making things up?" The ranked chunks should still be sensible. That is semantic — "vibes-based" — search doing its job.
  3. Swap docs for five real sentences from something you own — a lesson, a README, a page from the language app you want to build. Rerun. The pipeline is now your pipeline.
  4. (Optional) Uncomment the generate call with an OPENAI_API_KEY set, or point the function at whatever model you use.
