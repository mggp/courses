The query stops being sacred

Rewriting, expansion, and hypothetical documents — the fixes for the one retrieval failure that survived hybrid search.

~50 minutes  ·  Python  ·  lesson 3  ·  glossary

Why this lesson

At your fintech, the question rarely matches the document. An analyst asks "what happens when a customer can't pay?" — the policy says "the account enters a 30-day arrears workflow." KYC auditors, fraud teams, underwriters: they all phrase things differently from how policies and case notes are written. That gap is the query layer, and this lesson gives you the tools to bridge it — and the honesty to know which tool actually works.

The row that beat hybrid search

In lesson 3, every knob you tuned recovered something — except one row. "What does the tutor do when it cannot find an answer?" stayed at 0.00 through dense, BM25, fusion, every chunk size, every k. Not because retrieval was weak: because the question and the answer share no vocabulary at all — "cannot find an answer" vs "does not know rather than guessing". The failure lives in the query, and it has three standard fixes, each named by a paper:

Rewrite-Retrieve-Read

Prompt an LLM to rewrite the search query before retrieval. The paper that introduced the name is explicit about the motivation: "there is inevitably a gap between the input text and the needed knowledge in retrieval" (Ma et al., EMNLP 2023). The basic version is one prompt; the paper's advanced version trains a small rewriter with reinforcement learning from reader feedback — you don't need that to start.

Multi-query + RRF (RAG-Fusion)

Generate several rewrites, retrieve with each, and fuse the results with the RRF you built in lesson 3. RAG-Fusion (Rackauckas, 2024) does exactly this, "the generated queries contextualizing the original query from various perspectives" — with a warning you'll see for yourself: "some answers strayed off topic when the generated queries' relevance to the original query is insufficient."

HyDE — hypothetical document embeddings

Instead of rewriting the question, generate a hypothetical answer passage and embed that: "The document captures relevance patterns but is unreal and may contain false details" (Gao et al., 2022). Then the encoder's dense bottleneck filters the false details — you retrieve by a vector written in the corpus's own words.

The asymmetry, in one sentence. Rewriting keeps the query's vocabulary; HyDE switches to the answer's vocabulary. When the gap is between question-words and answer-words, the second approach is the more direct attack.

Build it

In exercises/lesson0004/, query_layer.py reuses the lesson-3 retrieval code and adds the three families. The gold set carries an optional query-layer set — rewrite, variants, and a hypothetical doc — for the hard question:

{
    "rewrite":  "How does the tutor respond when it has no answer?",
    "variants": [
        "What happens when the tutor cannot answer a learner's question?",
        "What does the tutor do if it is unable to answer?",
        "How does the tutor handle a question it cannot answer?",
        "How does the tutor respond when it has no answer?",
        "What happens when no answer can be found for the learner's question?",
    ],
    "hyde": "If no chunk is close enough, the tutor says it does not know rather than guessing.",
}

These strings are what a good LLM rewriter produces for this question — you'll regenerate them with your own model in the optional step. The harness runs four strategies per question: raw, rewrite, multi (RRF over all variants), and hyde.

  1. Run uv sync then uv run query_layer.py. You should see the aggregate: raw 0.83, rewrite 1.00, multi 0.83, hyde 1.00 — and the hard row reading 0.00 / 1.00 / 0.00 / 1.00.
  2. Read the surprise. The multi column did not rescue the paraphrase row — fusing all five variants put the gold chunk at fused rank 4, just outside k=3. RAG-Fusion's paper warned you: weak variants are not neutral, they are noise.
  3. Read the fragility table. The harness prints the fused rank of the gold chunk per variant: 7, 3, 6, 3, 6 — two hits, three misses. A single rewrite works only when its phrasing lands, and you cannot know which phrasing will land in advance. (The rewrite column is therefore an oracle: the best variant, picked after the fact.)
  4. One strong ballot carries the fusion. In GOLD, add the hyde doc as a sixth item in variants, re-run, and watch multi flip to 1.00. The fusion succeeds the moment a genuinely strong variant is in the set — which is exactly why RAG-Fusion quality hinges on the generator's rewrites.
  5. Confirm it wasn't the fusion weighting. Run uv run query_layer.py 3 10 — a steeper RRF doesn't rescue multi with the original five variants. The failure was signal, not the constant.
  6. Why HyDE wins here. Its hypothetical doc is written in the answer's own words ("does not know rather than guessing"), so its embedding lands on the right chunk at rank 1 — every time, on this row. It converts the query-answer asymmetry into the corpus's language instead of hoping a rewrite stumbles onto it.
  7. (Optional) Make it real. With an API key set (OPENAI_API_KEY, optionally OPENAI_BASE_URL), run uv run query_layer.py --live — the harness calls an LLM to generate the rewrites and hypothetical docs, then re-runs all four strategies. Compare its rewrites to the canned ones, and see whether its multi column carries the row.

Stuck? Ask your teacher

Primary sources for this lesson

"Query Rewriting for Retrieval-Augmented Large Language Models" — Ma et al., EMNLP 2023 is the anchor: it names the query-answer gap and the rewrite-retrieve-read pipeline, and its trainable rewriter is what production systems evolve toward. Its two siblings complete the trio: RAG-Fusion (multi-query + RRF, with an honest caveat about off-topic variants) and HyDE (the hypothetical-document paper). Read the abstracts, then the sections on their failure modes — each paper admits exactly the weakness you measured today.

Key terms: query layer, query rewriting, multi-query expansion, HyDE.
