Lesson 5 · Building AI Systems in Python

The generator stops being trusted on faith

Retrieval was never the whole story. The answer the model writes is a new object, and it needs its own check: faithfulness.

~45 minutes  ·  Python  ·  lesson 4  ·  glossary

Why this lesson

Lessons 1–4 measured one question: did the right chunk come back? But the fintech risk isn't a bad ranking — it's a confident wrong answer. A KYC auditor asks "does this customer appear on a sanctions list?" and the model answers from a chunk that says the opposite. A credit-risk summary quietly flips "no adverse history" to "adverse history noted". Retrieval metrics would call both runs perfect, because the right chunk was returned. This lesson builds the second measurement — faithfulness — that catches the answer itself.

Two questions, one pipeline

Every RAG pipeline answers two independent questions, and they must not be confused:

Retrieverecall@k — did the right chunk come back? → Generatethe model writes an answer → Checkfaithfulness — did the answer stay inside the chunk?

Recall@k (lessons 2–4) scores retrieval. Faithfulness scores the text the model wrote, against the chunks it was given. A pipeline can have perfect recall and zero faithfulness — the retriever hands over the gold chunk, and the generator writes something the chunk does not say. That is the failure this lesson measures.

Why retrieval metrics can't see it. Recall only knows whether a chunk is present in the top-k. It has no opinion about what happens next. The moment you add a generator, you add a new surface where errors appear — and it needs its own number.

The mechanic: decompose, check, score

Faithfulness is reference-free — it needs no gold answer, only the answer and the retrieved context. That matters, because writing gold answers is exactly the cost you're trying to avoid. The procedure has three steps, named by two papers:

1. Decompose the answer into atomic claims

An answer is not one fact; it is several. FActScore (Min et al., EMNLP 2023) breaks a generation into atomic facts and scores each one — because "generations often contain a mixture of supported and unsupported pieces of information, making binary judgments of quality inadequate." Their headline finding: ChatGPT achieves only 58% factuality on long-form biographies. Mixed answers are the norm, so you must score claim by claim.

2. Check each claim against the context

For each atomic claim, ask: does the retrieved context entail it? The tool is natural language inference (NLI): a model reads a premise and a hypothesis and labels the relationship entailment, neutral, or contradiction. Here the premise is the retrieved context and the hypothesis is the claim. RAGAS (Es et al., 2023) is the framework that made this the standard faithfulness recipe: "identify all claims in the response, check each claim to see if it can be inferred from the retrieved context."

  • entailment → the claim is supported by the context.
  • neutral → the claim isn't there at all → unsupported.
  • contradiction → the claim conflicts with the context → unsupported, and worse: confident wrongness.

3. Score

faithfulness = supported claims / total claims

Both neutral and contradiction count as unsupported. Only entailment counts. A 1.0 means every claim is grounded; a 0.0 means none are.

The NLI model is itself a model. It is a cheap, deterministic stand-in for a human auditor — not the auditor. It catches the polarity flips and invented claims that matter most, but it can be fooled. Treat a faithfulness score as a regression number you can run every build, and escalate to a human only when it drops.

Build it

In exercises/lesson0005/, faithfulness.py holds four cases. Each is a (question, retrieved context, generated answer) triple with the answer's atomic claims already written out (the --live step has the LLM decompose instead). The harness checks each claim with a local NLI model, cross-encoder/nli-MiniLM2-L6-H768 — 82M parameters, trained on SNLI and MultiNLI, runs on ordinary hardware.

One thing to notice before you run: in every case the context shown is the gold chunk. Retrieval did its job in all four — recall@k would be 1.0 across the board. The only thing that changes is the answer.

  1. Run uv sync, then uv run faithfulness.py. The first run downloads the NLI model (~130 MB). You should see four cases and an overall 2/5 = 0.40.
  2. Read the baseline. Case faithful scores 1/1: the answer restates the chunk in its own words. This is the good path — the generator wrote, and the writing stayed inside the context.
  3. Read the mixed answer. Case hallucination-sneaks-in scores 1/2: one claim is SUPPORTED, but "emails the support team for help" is NOT IN CONTEXT. A single sentence carried a hallucination — exactly the mixture FActScore warns about. This is why you decompose.
  4. Read the misread. Case right-chunk-wrong-claim scores 0/1: the gold chunk says the scheduler computes the review date, the answer says the learner manually requests it. Right chunk, wrong claim.
  5. Read the one that matters. Case compliance-polarity-flip scores 0/1 with CONTRADICTED: the chunk says the platform stores no recordings, the answer says it stores them. In a fintech this is the answer that ends a career. Retrieval would have scored it perfect.
  6. Watch the labels. Notice the two failure flavors: NOT IN CONTEXT (neutral — invented detail) and CONTRADICTED (reversed a fact). Both score 0 for faithfulness; the second is the dangerous one. Distinguishing them is why NLI has three labels, not two.
  7. (Optional) Make decomposition real. With OPENAI_API_KEY set, run uv run faithfulness.py --live — an LLM decomposes each answer into claims, then the same NLI model checks them. Compare the LLM's decomposition to the hand-written claims: decomposition is itself a place errors hide.

Primary sources for this lesson

"RAGAS: Automated Evaluation of Retrieval Augmented Generation" — Es et al., 2023 is the anchor: a reference-free suite spanning retrieval, faithfulness, and generation quality. Its faithfulness recipe (claims → inferable-from-context → supported/total) is what you built, and its faithfulness docs walk the Einstein example with a worked 0.5. "FActScore" — Min et al., EMNLP 2023 is the conceptual parent: decompose into atomic facts, score each, and the sobering 58% finding. The NLI model card, cross-encoder/nli-MiniLM2-L6-H768, documents the three labels you just used.

Key terms: faithfulness, atomic claim, NLI / entailment, answer relevance.
