Two stages of retrieval

Recall is cheap and blind. Reranking is expensive and sharp. Production retrieval is both, in that order.

~40 minutes  ·  Python  ·  lesson 5  ·  lesson 3  ·  glossary

Why this lesson

Your fintech document Q&A has a silent failure mode that lessons 3 and 4 did not close: the right policy chunk comes back fifth, and the generator only reads the top three. Retrieval "worked" — recall counted it a miss. Reranking fixes the ordering without anyone rewriting the question. This is the last retrieval-layer tool, and it is the one production systems bolt on first, because it is the highest-leverage single change you can make.

Recall and rerank: two stages, two prices

Everything you built in lessons 1–4 was recall: two systems — the dense bi-encoder and the lexical BM25 — scoring every chunk, fused with RRF. The bi-encoder is cheap because every chunk is embedded once and compared with a dot product — but the two texts never see each other, so a paraphrase like "cannot find an answer" vs "does not know rather than guessing" is invisible to it. BM25 is blind the other way: it only matches literal (stemmed) words. The fix is a second stage:

Recallbi-encoder + BM25, RRF — cheap, whole corpus, returns top-N → Rerankcross-encoder — reads each pair together, re-orders the top-N → Generatetop-k reaches the model

A cross-encoder reads the query and a passage as one input, attends token-to-token, and emits a single relevance score. It sees "cannot find an answer" ⇄ "does not know rather than guessing" because both phrases are in front of it at once. The price: no precomputation — one model pass per candidate. So you recall with the cheap stage, then rerank only the top-N. This two-stage shape is the canonical design, from the paper that invented it: "Passage Re-ranking with BERT" (Nogueira & Cho, 2019) — BERT over the top candidates, +27% MRR@10 on MS MARCO.

Why the recall stage missed — recapped

This closes the loop on the diagnosis you ran in lesson 2. The bi-encoder all-MiniLM-L6-v2 pools by averaging token vectors, so the gold chunk's distinctive words ("does not know", "guessing") contribute a whisper against the shared grammatical scaffolding, and the model ranks on token overlap rather than meaning. The cross-encoder is not subject to that pooling loss — it scores the relationship directly, which is why a generic relevance reranker, with no query rewriting and no domain tuning, can lift the miss that survived hybrid search and multi-query fusion.

Build it

In exercises/lesson0006/, rerank.py reuses the lesson-3 retrieval code (chunking, BM25, RRF, dense) and adds one stage: take the fused top-N and re-sort it with cross-encoder/ms-marco-MiniLM-L6-v2 (22.7M params, trained on MS MARCO passage ranking, MRR@10 of 39.01 — see its model card). The gold set is the same six questions as lessons 3–4.

  1. Run uv sync, then uv run rerank.py. You should see the mean jump from fused 0.83 → reranked 1.00, with the paraphrase row reading 0.00 / 1.00.
  2. Watch the reorder. Run uv run rerank.py --query "What does the tutor do when it cannot find an answer?" --gold "the tutor says it does not know rather than guessing". Fused top-3 is p2 p3 p4 — gold p9 sits at rank 5. Reranked top-3 is p3 p2 p9 — the cross-encoder pulled p9 to rank 3. No query was rewritten; the paraphrase became visible.
  3. Read the scores honestly. The cross-encoder gives p3 3.65, p2 0.09, p9 −2.14, p4 −4.90. Two lessons here: the absolute values are uncalibrated — negative scores are normal, only the order matters. And p9 clears p4 by ~2.8 points yet still only reaches rank 3, the very edge of k=3. The reranker still prefers p3 ("answers only from the course material") — this is a rescue, not a slam dunk.
  4. Recall is the floor. Run uv run rerank.py 3 3 — a rerank pool of 3. Gold p9 is at fused rank 5, so it never reaches the reranker, and the row stays 0.00. Reranking can only re-order what recall hands it. This is why you measure the recall stage's candidate pool, not just its top-k.
  5. The reranker has its own blind spots. Run uv run rerank.py 3 24 — rerank the whole corpus. The paraphrase row is rescued, but the "long-term recall sharp" row drops (gold p5 falls from rank 1 to rank 4): over the long tail of irrelevant chunks the cross-encoder's scores bunch up near −11.2, and three junk chunks (GDPR, daily streak, 2FA) sneak above the right one. Net mean is back to 0.83 — one row traded for another. Reranking a short candidate list sharpens recall; reranking everything reintroduces the cross-encoder's own errors.
