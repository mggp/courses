The six-question circuit

1 of 6 · RAG and evaluation

Question: Walk me through a RAG system. How do you know it works?

Compare your answer

I split documents into retrievable chunks, embed and index them, retrieve a small evidence set for the question, optionally rerank it, then give that context to the generator with instructions to cite or abstain. I evaluate retrieval and generation separately: recall at k asks whether the needed evidence crossed the context cut, while faithfulness asks whether each answer claim follows from that evidence. In a local capstone I measured both and found that a citation could point to a real chunk without proving the associated claim. I would also test answer relevance, latency, cost, and failure cases on a versioned evaluation set.

2 of 6 · Agents and MCP

Question: What makes a system an agent, and where does MCP fit?

Compare your answer

An agent is an LLM-driven control loop that chooses a next action, calls a tool, reads the observation, and continues or stops under application policy. A workflow has a path mostly fixed by code, so I prefer it when the steps are known because it is easier to test and constrain. MCP standardizes how a host application connects to server-provided tools, resources, and prompts; it does not supply the planning loop, memory policy, or authorization model. I have built a personal LangGraph tool and integrated MCP tooling into a maintained FastAPI service, which gives me a real boundary example without claiming every LLM feature is an agent.

3 of 6 · Safety

Question: How would you make a financial document assistant safe?

Compare your answer

I would treat safety as controls around the model, not as one system prompt. The data path needs tenant and document authorization before retrieval, versioned authoritative sources, retrieval evaluation, claim-level evidence checks, and structured output where the application needs typed decisions. Any consequential tool call needs application-side permission checks, input validation, idempotency where appropriate, audit events, and a fail-closed route. If evidence, authorization, or a required check is missing, the assistant should abstain or send the case to human review. Temperature and top-p change sampling; neither enforces policy or truth.

4 of 6 · Data architecture

Question: When would you choose a vector store, a graph database, or both?

Compare your answer

I choose from the access pattern. Vector search finds semantically similar evidence, so it fits questions whose wording differs from the source. A graph stores explicit entities and relationships, so it fits multi-hop questions such as which accounts share an owner and connect to a flagged merchant. A hybrid can use vector retrieval to find relevant text, extract or resolve entities, then traverse verified relationships. I would measure it against representative queries because adding a graph creates modeling, extraction, consistency, and operational costs.

Repair lesson: vector or graph

5 of 6 · Memory

Question: Explain short-term and long-term agent memory. Does persistence change the distinction?

Compare your answer

Short-term memory is state scoped to one run or thread, such as messages, tool results, a plan, and pending approvals. Long-term memory is selected information meant for later threads, such as a stable user preference or a prior outcome. A database can persist either, so durability does not decide the category. The host still has to select or retrieve information and place it into the model input, and the memory policy must define writes, ownership, correction, deletion, and context budget.

6 of 6 · Delivery and cloud

Question: Tell me about your cloud AI experience and how you would productionize an LLM feature.

Compare your answer

I have not operated Bedrock, Azure AI, or Vertex AI in production, so I would not claim that experience. My relevant base is maintaining FastAPI services, integrating MCP tooling, building a personal LangGraph tool, and implementing RAG and evaluation mechanics locally. I have a bounded personal Bedrock Converse integration behind an application-owned provider port; that taught me the runtime, Region, model identifier, IAM invoke permission, usage, latency, and failure boundary, but it is still a lab. For production I would keep provider code behind an adapter and design identity, network boundaries, secrets, retries, timeouts, rate limits, evaluation, observability, cost controls, rollout, and rollback around it.
