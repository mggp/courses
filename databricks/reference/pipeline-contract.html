Pipeline contract

Use this study device to turn a business request into testable inputs and outputs. “Pipeline contract” is a study label, not a Databricks product or an extra exam objective.

User input
The request plus required fields, identity, and conversation context.
Knowledge input
The facts the system must obtain. Name whether each source is live structured data, governed unstructured content, or an external service.
Action input
The parameters and authorization needed when a tool changes an external system.
Response output
The exact content, structure, citations, and fallback the user receives.
Action output
The state change, identifier, artifact, or confirmation produced by a tool.
Success check
An observable criterion such as accuracy, completeness, safety, latency, or cost.

Fast exam check

  1. Underline the verbs. “Answer” is a response; “create,” “update,” and “send” are actions.
  2. Circle required entities such as account_id, transaction_id, dates, or document types.
  3. Separate facts that can live in documents from facts that must be fetched from a live system.
  4. State what happens when identity, data, or authorization is missing.
  5. Only then choose the model, retrieval method, tools, or Databricks product.
