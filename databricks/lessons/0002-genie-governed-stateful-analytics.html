Genie for governed, stateful analytics

Use a Genie Agent when another agent or application needs a specialist that can turn business-language questions into SQL over governed structured data. Keep the same conversation ID for follow-ups. Keep business state somewhere else.

Guide objective, quoted exactly:
Enable multi-agent systems to leverage Genie Spaces or conversational API to retrieve data.
Current-name alert. Databricks renamed Genie Spaces to Genie Agents. The current Chat mode REST paths still contain /genie/spaces/, so exam wording, UI wording, and endpoint wording do not quite match. Official concepts; official API reference.

The mental model

A Genie Agent is a domain-specific analytics specialist. Authors configure datasets, example SQL, instructions, and semantic definitions. Genie uses those assets with Unity Catalog metadata to turn a natural-language question into SQL and, when possible, return the SQL, a result table, and a visualization. Official source.

Meaning
The knowledge store, instructions, example SQL, SQL functions, and trusted assets teach Genie the organization's terminology and approved analytical logic. Official source.
Data
The agent works with Unity Catalog tables, views, metric views, and related structured objects. Chat mode does not answer from PDFs or Word files. Official source.
Compute
A pro or serverless SQL warehouse runs the generated SQL. The author who configures the warehouse supplies the embedded compute credentials. Official source.
Governance
For ordinary end-user access, Unity Catalog evaluates data access as the end user's identity. Row filters and column masks therefore remain enforceable per user. Official source.
Conversation
The Conversation API stores a thread of messages under a conversation_id. A follow-up sent to that ID uses the messages already in the conversation. Official API reference.

The table list in the Genie Agent is context, not a security perimeter. Current documentation says Genie can query tables outside that list when the caller has Unity Catalog access and the prompt, instructions, or metadata lead it there. Use Unity Catalog privileges, row filters, and column masks as the boundary. Official source.

What “stateful” means here

The state is the conversation history that Genie uses to resolve a follow-up such as “Now split that by region.” It is not a transaction record, workflow checkpoint, customer profile, or durable application memory. The first sentence is documented API behavior; the second is the architectural boundary implied by the API's message-thread model and Databricks' advice to start a new conversation for each session. Message behavior; session guidance.

Correct reuse. “Which five stores had the most returns last quarter?” followed by “Only show Spain” belongs in one conversation because the second question depends on the first.
Start fresh. A different user begins a new analytical task. Create a new conversation. Databricks warns that reusing threads across sessions can introduce unintended context and reduce accuracy. Official source.

The Chat mode API lifecycle

StepCallWhat to retain
1. Start POST /api/2.0/genie/spaces/{space_id}/start-conversation conversation_id and message_id. Official API reference.
2. Wait GET .../messages/{message_id} Poll until COMPLETED, FAILED, or CANCELLED. Databricks recommends polling every 1 to 5 seconds with backoff and a practical timeout. Official source.
3. Read Inspect message attachments A response can carry text, generated SQL, a visualization, and query-result metadata. Official API reference.
4. Fetch rows GET .../attachments/{attachment_id}/query-result Use this when the message has a query attachment and you need the SQL result payload. Official API reference.
5. Continue POST .../conversations/{conversation_id}/messages Reuse the same conversation_id only while the follow-up belongs to that session. Official API reference.

The REST API is asynchronous. The Databricks SDK's start_conversation_and_wait and create_message_and_wait helpers hide the polling loop, but the underlying message lifecycle still exists. Databricks uses these helpers in its official Apps example. Official example.

Run this in a Databricks notebook

Use a Genie Agent you can run, replace the ID, and ask a question that matches its domain. In a Databricks notebook, WorkspaceClient() uses the notebook's available Databricks authentication. The two SDK calls below start one conversation and then preserve its context for a follow-up. Official SDK pattern.

from databricks.sdk import WorkspaceClient

SPACE_ID = "replace-with-your-genie-agent-id"
w = WorkspaceClient()

first = w.genie.start_conversation_and_wait(
    space_id=SPACE_ID,
    content="Which five products had the most returns last quarter?",
)

print("conversation:", first.conversation_id)
for attachment in first.attachments or []:
    if attachment.text and attachment.text.content:
        print("ANSWER:", attachment.text.content)
    if attachment.query and attachment.query.query:
        print("SQL:\n", attachment.query.query)

follow_up = w.genie.create_message_and_wait(
    space_id=SPACE_ID,
    conversation_id=first.conversation_id,
    content="Restrict that result to Spain and keep the same ranking.",
)

for attachment in follow_up.attachments or []:
    if attachment.text and attachment.text.content:
        print("FOLLOW-UP:", attachment.text.content)
    if attachment.query and attachment.query.query:
        print("FOLLOW-UP SQL:\n", attachment.query.query)
Learning check. Inspect the second SQL query. It should reflect both the original measure and the new country restriction. Then start a separate conversation with the follow-up sentence alone. Compare the result. That contrast makes conversation state visible.

Identity is part of the architecture

A direct user call and a Databricks App call need not run as the same identity. A Databricks App has its own service principal for app authorization. It can instead use on-behalf-of-user authorization when the result must respect each caller's Unity Catalog permissions, including row filters and column masks. Official source.

When you add a Genie Agent as an App resource, Databricks grants the app service principal permission on that agent, and the service principal also needs privileges on the underlying data. Official source. Therefore, “the Genie Agent is governed” is incomplete. You must name the caller identity whose privileges Unity Catalog will enforce.

Where Genie fits in a multi-agent system

A multi-agent orchestrator treats specialist agents as tools. Current Databricks guidance uses a Genie Agent for structured-data analysis and a Knowledge Assistant or other agent for document or domain work. In the custom Databricks Apps template, Genie connects through the built-in Databricks MCP server and requires the Genie Agent ID plus CAN_RUN. Official source.

Common mistakes

  1. Calling every message “stateless.” A follow-up sent with the same conversation_id uses prior messages. Official API reference.
  2. Calling the conversation a memory database. It is session context. Databricks advises one new conversation per session. Official source.
  3. Trusting the configured table list as access control. Genie can reach other tables when Unity Catalog permits it. Official source.
  4. Ignoring the execution identity. A user token and an app service principal can see different data. Official source.
  5. Reading only the text attachment. Applications that need evidence should also retain or display the generated SQL and query results. The API represents these as separate response attachments. Official API reference.
  6. Sending documents to Chat mode. Chat mode is for structured data. Use an appropriate document-capable agent and orchestrate it with Genie when the question spans both. Official source; multi-agent pattern.

Retrieval practice

A support assistant answers policy questions from manuals and account questions from governed billing tables. A user asks, “Why did my invoice rise?” and then, “Compare it with the same month last year.” Different regions must see only their own accounts.

Without looking back, write down the specialist, the routing choice, the state identifier to preserve, and the security identity requirement.

Check a model answer

Route billing analysis to a Genie Agent and policy-document questions to a document-capable specialist. A Supervisor Agent is the first managed choice for coordinating them; use a custom Databricks App if the routing requirements exceed it. Preserve the Genie conversation_id for the year-over-year follow-up. Use on-behalf-of-user authorization, and enforce regional visibility with Unity Catalog privileges or row filters. Do not use the conversation thread as the billing system of record. Orchestration source; state source; authorization source.
