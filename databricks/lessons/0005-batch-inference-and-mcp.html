Batch inference and MCP

These objectives sit next to each other in Section 4, but they solve different problems. ai_query applies a model to data through SQL or Python. MCP gives an agent a standard way to discover and call tools. Exam objectives; ai_query guide; MCP overview.

Your win. Given a workload, decide whether it needs batch inference or an agent tool. Then choose the right ai_query arguments or MCP server type without being fooled by endpoint, hosting, or permission distractors.

Start with the split

QuestionMechanismTypical cue
Should a model transform every selected row?ai_querySummarize, classify, extract, embed, or score a table column. Databricks describes ai_query as a general-purpose AI Function for supported models in SQL or Python. Source.
Should an agent choose and call a capability while reasoning?MCP serverSearch an index, query governed data, call a SaaS API, or run custom business logic. MCP connects agents to tools, resources, and prompts. Source.

The useful boundary. Batch inference is data-driven: the query selects the rows. MCP is agent-driven: the model decides whether and how to call a discovered tool. A solution may use both, but one does not replace the other.

Read ai_query(endpoint, request) literally

The function invokes an existing Model Serving endpoint and parses its response. It does not create or deploy the endpoint. The endpoint name is a string literal, it must be in the same workspace, and the function definer needs CAN QUERY. Function reference.

endpoint
A Databricks-hosted model service, provisioned-throughput model endpoint, external model endpoint, or custom model endpoint supported by ai_query. A system.ai model service needs no endpoint provisioning. External and custom models need their respective serving endpoints. Supported model types.
request
For a Databricks Foundation Model APIs or external model endpoint, pass a string expression. For a custom model endpoint, pass one column or a STRUCT whose field names match the model inputs. Argument rules.
returnType
Use this for a custom endpoint when Databricks cannot infer the output from a model schema. On Databricks Runtime 15.2 and later it is optional when a schema is available. Do not confuse it with an LLM output instruction. Argument rules.
responseFormat
Use this with a chat foundation model to request structured output. It accepts a DDL-style schema or a JSON response-format document. It requires Databricks Runtime 15.4 LTS or later. Structured output.
modelParameters
Pass constant chat, completion, or embedding parameters such as temperature and maximum tokens. These values cannot vary by row. Parameter rules.
failOnError
The default is true. With false, endpoint failures produce a result STRUCT containing response and errorMessage, so successful rows survive. Other kinds of errors can still fail the whole query. Error behavior.

Choose ai_query only when it earns its flexibility

Start with a task-specific AI Function when one matches the job. Use ai_query when you need your own prompt, model parameters, output format, or a custom, fine-tuned, or external model. Databricks decision guidance.

Make batch inference behave like a data pipeline

  1. Send the full selected dataset in one query. AI Functions handles parallelism, retries, and scaling; manually splitting it into small batches can reduce throughput. Best practices.
  2. For a large run, set failOnError => false and persist both successful responses and row-level endpoint errors. Best practices.
  3. Use structured output when downstream SQL needs fields rather than prose. Structured output.
  4. Put repeatable production work in a Lakeflow pipeline, scheduled Databricks workflow, or Structured Streaming workflow. Those pipelines can include ingestion, preprocessing, inference, and post-processing. Pipeline patterns.

Current requirements: AI Functions are unavailable on Classic SQL warehouses. The ai_query guide requires Databricks Runtime 15.4 LTS or later and recommends 18.2 or later for current features and performance. Source.

Run a two-row extraction

Run this in a SQL warehouse that supports AI Functions. If system.ai.gpt-oss-20b is unavailable in your region, replace it with a supported chat model service shown in your workspace. The query asks for typed output and preserves row-level endpoint errors. Model availability and batch guidance; Syntax.

WITH tickets(ticket_id, body) AS (
  SELECT * FROM VALUES
    (101, 'The dashboard is blank after login.'),
    (102, 'Please add two seats to our subscription.')
), inferred AS (
  SELECT
    ticket_id,
    ai_query(
      'system.ai.gpt-oss-20b',
      'Classify this support ticket: ' || body,
      responseFormat => 'STRUCT<category:STRING, urgency:STRING>',
      failOnError => false
    ) AS inference
  FROM tickets
)
SELECT
  ticket_id,
  inference.response AS classification,
  inference.errorMessage AS error_message
FROM inferred;

Check that each row has either a classification or an error. Then change the schema to STRUCT<category:STRING, urgency:STRING, reason:STRING> and rerun it. That small edit makes the role of responseFormat hard to forget.

MCP is one interface with three hosting choices

Managed, external, and custom servers expose the same MCP interface to agent code. The server URL and authentication differ. Databricks' databricks-mcp client can connect to all three. Client and URL patterns.

ChooseWhen it fitsOwnership and control
Databricks managed MCP serverA ready-to-use Databricks tool already exists for the job: Genie One, one Genie Agent, AI Search, Databricks SQL, or Unity Catalog functions.Databricks hosts the server and manages authentication. Unity Catalog still enforces access to the tool and its data. Managed server list.
External server registered as an MCP ServiceAn MCP server already runs outside the Databricks app, or a built-in system.ai MCP Service connects to a SaaS provider. You want governed discovery, credentials, grants, policies, audit, and usage through Unity Gateway.A Unity Catalog HTTP connection stores the server URL and credentials. The MCP Service is the governed Unity Catalog securable and proxy. The external server must use Streamable HTTP and be reachable from the serverless compute plane. Registration and requirements.
Custom MCP server hosted as a Databricks appYou need tool behavior that no managed server supplies, or you want to deploy an existing Python or third-party MCP server inside Databricks.You own the server code and deployment. Databricks Apps hosts it, Apps permissions control access, and the server must use an HTTP-compatible transport. Custom server guide.

The naming trap. An MCP Service is a Unity Catalog securable for a registered or Databricks-provided service. It is not a synonym for every MCP server. “External” means the server runs elsewhere and Databricks proxies it. “Custom” means you host the server as a Databricks app. MCP Service definition; custom hosting.

Permissions follow both the server and the resource

  • A caller of an MCP Service needs EXECUTE on the service plus USE CATALOG and USE SCHEMA. End users do not need USE CONNECTION; granting it would let them bypass the MCP Service's tool selection, policies, and audit path. MCP Service permissions.
  • An agent also needs access to each underlying resource its MCP tools use, such as CAN_RUN on a Genie Agent or SELECT on an AI Search index. Agent deployment permissions.
  • An MCP Service can expose only selected tools. Service policies can allow, deny, or require approval for individual calls. Unity Gateway can rate-limit calls and records usage and audit data. MCP Service governance.
  • For external providers, network reachability and Unity Catalog privileges are separate. A grant does not open an egress path, and an allowed network destination does not grant EXECUTE. Network and privilege layers.

Common mistakes

  1. Calling ai_query an endpoint deployment command. It only invokes an existing endpoint or model service. Source.
  2. Using returnType to control an LLM's prose shape. Use responseFormat for structured chat-model output; returnType describes a custom endpoint's returned data type. Source.
  3. Looping over rows or hand-making tiny batches. Submit one dataset query and let AI Functions manage parallelism, retries, and scaling. Source.
  4. Leaving failOnError at its default for a large batch, then losing all progress to one endpoint failure. Set it to false and retain the error column. Source.
  5. Building a custom MCP server for AI Search, Genie, Databricks SQL, or an existing Unity Catalog function. Check the managed list first. Source.
  6. Calling every non-managed integration “external.” A server hosted as a Databricks app is custom even if its tools call a third-party API. Source.
  7. Granting the MCP endpoint but forgetting its underlying data or tool permissions. The agent needs both. Source.
