Let content set the breakpoint

A breakpoint is not a phone model. It is the width where the current composition can no longer preserve its relationships.

Your win: calculate a layout's width budget and place its breakpoint where that budget stops fitting.

Start with the layout budget

Give each region a minimum useful width. Add the gap and outer insets. The sum is the smallest width that supports the multi-column composition.

17rem primary + 11rem secondary + 1.25rem gap + 2.5rem insets = 31.75rem

Below roughly 32rem, one of those constraints must give. Shrinking both regions preserves the grid but damages the content. Stacking the secondary region preserves both.

web.dev recommends choosing breakpoints from content rather than device classes. Device names describe hardware. Your breakpoint describes a composition.

Preserve relationships, not coordinates

Wide and narrow layouts are two arrangements of the same priorities. The primary reading task comes first in both. The summary sits beside it when space permits and follows it when space does not.

This is why source order matters. A desktop grid can place regions almost anywhere. When the grid collapses, the document order should still produce the intended reading order.

Use the right available width

If this composition fills a page, a viewport breakpoint may describe its available room. If it lives inside a dashboard panel, the panel width matters instead. The design question stays the same even if the implementation changes from a media query to a container query.

Reflow is a floor, not the whole design

WCAG 2.2 requires most vertically scrolling content to work at a width equivalent to 320 CSS pixels without losing information or forcing scrolling in two directions. Passing that check prevents a serious failure. It does not prove that every intermediate width is well composed.

Write the critique

“The two-column layout persists below the minimum useful width of its regions, so the summary becomes cramped before the mobile breakpoint. Stack the summary when the composition falls below 32rem. Preserve the primary-first source order and keep type, color, and content unchanged.”

Do this on one of your pages

  1. Choose one multi-column region and name the job of each column.
  2. Estimate the minimum useful width of each column, then add gaps and insets.
  3. Resize slowly through that width and record the first visible failure.
  4. Write one revision request that changes composition only.
