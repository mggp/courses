Give text a role before a size

Weak typography often comes from styling each element in isolation. A type system starts by deciding what job each piece of text performs.

Your win: turn a flat code-entry screen into a clear task using typography alone.

Roles create the system

“Make this 28 pixels” describes an output. “This is the task heading” describes why the output exists. Assign the role first, then choose a size, weight, and line height that distinguishes it from nearby roles.

Task headingStarts the action and carries the strongest textual emphasis.
Control labelIdentifies one field. Compact and clear, without competing with the task.
Supporting copyExplains or reassures after the task is understood. Comfortable to read, but quieter.

The GOV.UK Design System recommends consistent heading styles so readers can recognize content structure across screens. Consistency matters more than finding a perfect font size for one card.

Use contrast sparingly

Size, weight, and line height all create typographic contrast. You rarely need to push all three. Start with size for role, add weight when the distinction is still weak, and use line height to suit the reading task.

Headings usually tolerate tighter line height because they contain fewer, larger words. Multi-line supporting copy needs more room. Do not make body text tiny or cramped just to quiet it. That trades hierarchy for legibility.

Semantics and appearance are separate contracts

An <h1> describes document structure. A large visual style creates emphasis. They often belong together, but changing the font size does not repair incorrect heading markup. GOV.UK notes that rare visual departures from the semantic hierarchy need accessibility testing.

W3C does not require authors to set every paragraph to 1.5 line height. WCAG 2.2 requires the interface to survive a user override to that value, along with larger word, letter, and paragraph spacing, without losing content or function.

Write the critique

“The instruction and reassurance use similar type sizes, so their roles are ambiguous. Promote the instruction to the task-heading style and demote the reassurance to supporting copy. Keep spacing, color, and layout unchanged.”

Do this on your code screen

  1. Name the role of every visible text element before measuring it.
  2. Record the size, weight, and line height used for each role.
  3. Find two different roles whose typography is too similar or one shared role styled inconsistently.
  4. Write one revision request that changes typography only.
