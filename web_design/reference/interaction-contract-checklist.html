Quick reference

Audit the control's promise

A familiar control teaches people what will happen before they use it. Check the cue, behavior, and result as one contract.

1. Predict from the cue

Hide the implementation. From the label, shape, icon, position, and current state, write what you expect the control to do.

2. Name the pattern

Classify the task before styling it. Navigation changes location. A disclosure reveals content. A toggle changes a persistent setting.

3. Compare the behavior

Activate the control by pointer and keyboard. Record the change in content, location, focus, and state.

4. Inspect the feedback

The interface should expose the current state and the result of the action. A silent delay or hidden change makes a correct pattern feel broken.

5. Keep one contract

If the prediction and behavior disagree, change the cue or the behavior. Do not decorate the mismatch.

6. Check the semantics

Use the native element where possible. Expose the control's name, role, and state to assistive technology.

A critique sentence

“The chevron and row treatment promise an inline disclosure, but activation navigates away. Keep the editor in place, reveal the controls below the row, and expose the expanded state.”
