# Teaching notes

- Use the learner's software-engineering experience as a bridge, especially invariants, contracts, debugging, and systems. Do not reduce design to engineering.
- Start with diagnosis before aesthetics. The learner's immediate problem is seeing and naming why generated UIs feel wrong.
- Planned path: attention and hierarchy; spacing and grouping; typography and rhythm; layout and responsive composition; interaction patterns; visual languages; design systems; briefing and critiquing AI output.
- Each lesson should end with a sentence the learner could use in a real design critique.
- Revisit concepts through new interfaces rather than repeating definitions.
